Sequential vs Parallel Requests

Two patterns for the same problem: a page needs several answers from the server before it can show itself. This page explains the problem and both patterns from the ground up, and defines every term. The lesson after it lets you run them.

The problem

A profile page shows the user, their recent orders and some recommendations. Each comes from its own endpoint, and none of them needs another's answer to be asked. The page cannot finish until all three have arrived, so the time the user waits is decided by how the page asks.

Sequential requests

Ask, wait, then ask the next. Each await holds the next call back until the previous answer is in. The total wait is the sum of every call.

user          ████
orders            ████
recommendations       ████

What you get: code that reads top to bottom, and a natural place to stop when one call fails.

What it costs: the user waits for the sum. Each call you add makes the page slower by its whole length.

Parallel requests

Ask for everything at once. Start every call, then wait for the set with Promise.all. The total wait is the slowest call.

user          ████
orders        ████
recommendations ████

What you get: the page waits only as long as its slowest answer.

What it costs: more load on the server at the same moment, and you have to decide what to show when some calls fail and others succeed.

Terms

Request waterfall
Calls that run one after another when they did not need to, drawn on a timeline as steps going down and to the right.
Independent calls
Calls whose inputs do not include each other's outputs. Only these can run in parallel.
Promise.all
Waits for every promise in a list and gives back all the results. If any promise rejects, it rejects at once with that error.
Promise.allSettled
Waits for every promise and reports each one as fulfilled or rejected, so one failure does not hide the other answers.
Latency
The time from asking to receiving an answer. Here it is measured in the browser with performance.now().
Neither pattern is always right. Independent calls should run in parallel. Dependent calls cannot, and forcing them to only moves the waiting somewhere harder to see.
